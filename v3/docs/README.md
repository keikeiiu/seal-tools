# v3 documentation

`v3/docs/` holds one folder per KIND of document, the same rule as `v2/docs/`:

| folder | holds | rule |
|---|---|---|
| [spec/](spec/README.md) | how v3 works NOW | read this before changing behaviour; update it in the same commit |
| [plans/](plans/README.md) | proposals, work not yet done | a plan is never status: its row on that board is |
| [backlog/](backlog/README.md) | decided or named work, not ideas | [OPEN.md](backlog/OPEN.md) is the living list |
| [investigations/](investigations/README.md) | measurements and analyses whose findings are the value | findings stay true whether or not anything is built from them |
| [diagrams/](diagrams/README.md) | generated run-flow pages | v2's eight tool flows, rebuilt for v3, plus the calibration workflow; all Archify-checked |
| [records/](records/README.md) | dated history | records remember; they do not describe now |

The v2 docs tree ([../../v2/docs/](../../v2/docs/)) remains the current build's documentation until
v3 cuts over; v3 keeps its own fresh tree rather than moving v2's (PLAN-V3-CORE §13.5).
